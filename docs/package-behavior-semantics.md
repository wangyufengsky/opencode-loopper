# 工作包语义一致性三阶段实施

本轮目标：把自然语言中的条件、例外、状态转换和不变量转为可检查的有限域义务，再用具体反例帮助模型在有限次候选提交内修复。形式化通过仅适用于声明的有限域，不证明自然语言已完整形式化。

## 第一阶段：独立义务及有限域内核（0.3.76）

新增 `PackageBehaviorContract`：变量有 BOOLEAN/ENUM/INTEGER 类型、INPUT/OUTPUT 角色和显式有限取值。整数仅表示列出的离散值，不隐含区间完整性。事件为稳定键；义务绑定冻结来源、前置表达式和完整可观察结果。状态前值和后值必须是不同变量，后值不能用于前置条件。候选分支只引用义务，不能改写义务。跨阶段不变量表达为前状态与后结果之间的谓词。

支持 eq/ne/all/any/not/true/false。条件“或”保留全部适用赋值；例外通过显式否定和优先级条件表达，无默认拒绝、默认成功或隐式 first-hit 规则。所有输出必须有值，尚未说明的行为不可由候选自行补成义务。

纯检查器先验证冻结义务可达、无相互冲突且满足不变量，再检查候选：不可达条件、重叠冲突、未被义务支持的行为、遗漏覆盖、不变量违反。报告包含稳定标识、关联场景/来源、具体赋值、期望/实际与修复动作。冻结模型有矛盾归为 SOURCE_MODEL_UNCONFIRMED，不能伪装成已证实业务待决。

边界：32 个变量，每域最多 32 个值；64 个义务/候选分支，32 个不变量；表达式深度 6、128 节点，每算子最多 32 子式。枚举上限 4096 个赋值；超出返回 UNKNOWN，不能作为 UNSAT/通过。单次报告最多 32 个根因反例，修复后完整重检。未建模来源显式列出；来源引用和形式化通过均不等于全文语义证明。

本阶段仅交付内部内核与回归，生产 V2 接受路径仍按原合同工作。

## 第二阶段：有界 SAT 与反例修复（0.3.77）

使用 SAT4J Core 2.3.6 的有限域 one-hot 和 Tseitin CNF 编码，查询可达性、冲突和遗漏。每查询最多 100ms、每候选总计 2 秒/4096 查询，编码最多 40000 子句和 16000 SAT 变量。预算在查询前检查，求解器超时返回 UNKNOWN；不可把 unknown 或未查询条件当 UNSAT。反例返回前独立求值，只展示公式相关变量。200 个固定随机公式与小域穷举比较，并覆盖双重否定等价变换、否定变异和状态互斥。

生产 V2 Schema 增加可选 `behaviorBranches`（scenarioKey / obligationRefs / event / when / effects）。旧运行没有冻结义务时拒绝此字段；新输入带冻结义务时每个场景恰好绑定一个分支。所有 OUTPUT 必须赋值，禁止额外未获义务支持的行为。场景 precondition/action/observableResult/invariant 由服务端生成，候选同名文字不作为第二套行为合同。原文及其他非形式化材料继续显式保留；编译器只对声明有限域作证明。

反例沿现有 `actual` / `expected` / `repairHint` 以及稳定 `SEM-` 标识进入持久化回执；场景顺序变化不改变同一反例的身份。每次完整重提重检所有义务。最多返回 32 项反例，达到上限标记 diagnosticsComplete=false；UTF-8 边界继续适用。源模型矛盾保持“尚未确认”，候选不能改写冻结义务。此阶段编译接入可独立调用，生产自动准备/冻结将在第三阶段完成。

算法实现与依赖来源：[SAT4J 官方 Core 说明](https://www.sat4j.org/download.php)、[发布者 Maven 元数据](https://repo.maven.apache.org/maven2/org/ow2/sat4j/org.ow2.sat4j.pom/2.3.6/org.ow2.sat4j.pom-2.3.6.pom)。依赖声明 EPL 1.0 / LGPL 2.1；原始库以未修改 JAR 嵌入 Spring Boot，保留其许可元数据。

## 第三阶段：生产来源复核和评测（计划）

新运行冻结语义策略；历史会话及已接受合同保持原规则。复杂工作包最多一次结构化整理，加最多一次独立只读来源复核（用户已授权）；简单包不增加调用。来源复核只核对原文与义务的对应、遗漏和矛盾，不产生执行权限。准备、复核、候选校验分别持久化，文件/网络/模型操作不进入纯校验策略。

同步 MCP Schema、固定 Prompt、服务端编译、下游角色交接和诊断展示。新独立案例覆盖变异、语义等价写法、来源遗漏及恢复/停止；Luna 结果绑定候选与清单，实际请求数不可得仍为 null，GEPA 不绕过 200 次实际请求前置门禁。生产性能和自然语言正确率只有实测后才能报告。
