# 0.3.95 故事统计启动交接与工作区忽略规则

## 定位与修复

- 首次 Start 原先先申请队列/租约、准备目录并采集 Stage 基线，直到执行者的首条业务提示才等待退役 Designer 的统计 complete。complete 仍操作项目文件时，启动预检/基线采集可能与它重叠。新增 `TaskStartPreflight`，在首次入队、执行时钟及工作区副作用之前完成已有统计交接，并在返回后复核 Task 版本/状态。保留执行者业务提示前的统计 start 和原有失败/取消语义。
- Stage/Direct 私有 Git 原先独立决定忽略与索引成员，遗漏来源仓库的 `.git/info/exclude`、`core.excludesFile`、大小写配置和源索引的跟踪身份。可导致被原仓库忽略的 `.aicoding` 文件进入既有文件确认；反过来，已跟踪但匹配忽略规则的代码会被漏掉。
- `WorkspaceSnapshotFiles` 统一通过源 Git 的 `ls-files --cached --others --exclude-standard` 获取基线与新增文件清单，以有界 NUL 路径清单写入私有索引。原仓库索引保持不变，已跟踪文件继续被检查，项目 `.git` 和整个受管数据目录排除。无 Git 的目录保留私有 Git 的 `.gitignore` 行为。Stage/Direct 和 Direct 包检查点共用同一规则。
- 基线创建/稳定性失败新增明确中文原因和恢复提示，避免丢失关键语义后只显示“项目目录失败”。
- 既有冻结树、已完成审查与历史错误不自动改写；重做生成的新 Stage 使用修正后的清单。确认范围外文件只授权当前内容差异，不替代确定性验收或双 Judge 的业务结论。
