# 开发公约按需加载与版本更新后的本地服务交付

## 范围

按用户要求，结合 [OpenAI 关于技能与提示的说明](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) 调整开发规则：行为修改读取受影响合同与测试，纯文案和局部解释不强制全仓库调查；新增实现模式才优先查找相似实现。验证按任务分类，通过后继续完成交付，只有输入变化、失败或具体风险才补充验证。

根公约保留 MCP 核心原则，把具体反馈、同会话修正、通道例外、冻结兼容和独立预算移到 OpenCode 权威合同，未改变产品协议或运行提示。

新增持续授权：每次更新版本且完整 JAR 通过门禁后，检查当前环境中的本项目 Loopper 服务，无实例则启动，有实例则替换为本次新版本，实际运行验证通过后再交付。同步移除原先禁止本地服务替换或要求单独授权的冲突表述；远端推送、Release 和部署仍需相应授权。

开发文档明确实例归属、活动产物保护、既有配置、正常停止证明、完整数据备份、正式启动器、进程持续运行及健康/版本/页面/历史核验。启动或迁移失败保留恢复证据，不把构建成功报告为服务更新成功。
