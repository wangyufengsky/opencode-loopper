# 0.3.97：故事统计 20 秒全流程与停止协议修复

## 修改与证据

从 0.3.95 基线开始，对原生 story 插件每次 start、continue、complete 注入真实 20 秒延迟；覆盖 start 明确失败后 continue 再等待 20 秒成功。先完成场景诊断，再集中修改，再执行统一回归。0.3.96 候选完成全部 23 项后发现剩余并发问题，保留失败记录，完成下一批修复后重新构建本版本并重跑全部场景。

本次完整交付包含四项修复：

1. 等待统计时已经停止的旧业务提示不能迟到投递，防止设计取消后再提问、阻塞 complete。普通停止与统计取消保持不同语义，新恢复提示仍可执行。
2. 同一执行轮次的正常收尾与租约协调共享整个工作区冻结操作，防止重复捕获和 READY 检查点被错误改成失败。
3. 同一任务的取消请求与后台 STOPPING 收尾共享远端停止证明和 Session 写入结果，避免 20 秒等待后再次用旧版本写入，导致用户收到 HTTP 409。
4. 暂停期间被停止修订拦截的旧提示不进入业务失败恢复，防止 Session 先 FAILED 后又 ABORTED。意外线程中断仍按独立失败处理。

三个新增测试类在相应修复前均取得实际失败证据：`OpenCodeBusinessPromptCancellationTest`、`TaskWorkspaceCheckpointConcurrencyTest`、`TaskStopCoordinationIntegrationTest`。最后一个类覆盖重复用户取消、用户取消与后台收尾并发，以及暂停尚未落库时旧提示返回。保留原状态版本检查与停止证明要求，没有通过放宽 CAS 或伪造停止结果消除异常。

执行者到评审的统计合同保持：执行者业务结果先落库、会话退役后 complete；双 Judge 不新开故事统计。正常交接、complete 期间取消、范围外修改确认后进入双评审均纳入本次原生矩阵。每个场景在任务开始前配置根目录 `.gitignore`，插件等待期间实际写入 `.aicoding/runtime`，验证差异与范围外确认不包含这些文件。
