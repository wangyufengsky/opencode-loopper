# 0.4.70 知识库两批次优化

本次沿知识库检索、原文读取、引用、模型回合、历史刷新及目录/Git 分页流程落实两批优化。保留 MCP 优先、项目范围内原生只读兜底、原消息幂等、冻结来源和已保存证据边界。

## 第一批：正确性与恢复

- 文档按连续文本检索同一逻辑内容的内部字符分段，修复字段和中文词句跨 12000 字符边界漏检；命中带 `section` / `textOffset`，读取有界原文窗口，保持原 SHA、行号及旧分段读取兼容。Office/PDF 不跨不同页、幻灯片或工作表拼接句子。
- 精确消息连续两次正常结束但无答案时结束为可恢复失败，保留草稿/思考/调用；核对期间补到答案仍完成成功，不重发。页面“重新提问”恢复输入框，由用户发送新回合。
- Git 在首批 1000 条没有命中时仍返回继续游标，后续扫描使用冻结引用 SHA；每批有界、持久化页可重放，新提交不混入旧查询。

## 第二批：刷新与扫描成本

- 增量消息接口每页 50 条，前端保留已加载历史，只读取最后已知回合及其后的消息，断线后继续分页追赶；180 ms 合并事件，保留累计用量高水位并丢弃跨会话迟到结果。
- 每轮知识 HTTP 观测复用一份远端消息列表；精确当前消息与全会话累计用量分别投影，待回答问题优先处理。无变化轮询不发失效事件，工具/问题变化独立通知。
- 目录后续页复用首次扫描的元数据，有界缓存 16 份 / 400 万字符 / 5 分钟；游标绑定路径身份与筛选，每次读取仍检查来源、路径和原文件版本。服务重启或缓存过期要求重查。
