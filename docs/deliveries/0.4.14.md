# 0.4.14 模板分析 MCP 提交

本次将新模板 V5 的代码审查和贡献分析改为调用私有 `submit_template_analysis` 工具。工具返回结构化校验问题和提交 revision，模型在同一会话修正；幂等回执独立持久化。候选接受不完成批次，仍须远端终态证明、完整报告校验与同批双 Judge PASS。V1–V4 保留冻结文本协议。

新增 V80 提交回执表和仅允许本代精确模板工具的无文件/命令权限配置。回执校验 Task/Attempt/Session 与运行代际，拒绝旧 revision、跨身份和取消后的新提交；同键同内容重放返回原结果。任务删除先显式清理回执，随后清理批次，并以同一事务回滚。原有 Git、报告归属、评分、双评审和发布边界保持。

OpenCode `finish=length` 被识别为单次生成长度耗尽，模板任务显示具体原因。本次未修改 OpenCode/Provider 的 token 上限、用户模型或 thinking 配置。故障中的 32,000 上限来自当前 OpenCode 1.18.18 默认值，当前进程没有输出上限环境覆盖；MCP 无法反馈在工具调用发生前就被截断的生成。
