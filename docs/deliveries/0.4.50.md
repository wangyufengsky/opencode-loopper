# 0.4.50 本地交付：代码审查批次重试、恢复与取消

针对代码审查中单批查询异常导致整任务等待、失败清单隐藏，以及状态/列表读取失败阻断取消的问题，分离传输检查、模型重新分析与停止确认。

- 新代码审查、贡献报告及快照审查任务冻结 `batchMaxRetries=3`：首次失败后额外最多自动重试三次，等待 10、20、40 秒；只有可重试失败且旧会话已确认结束才能创建新代次。成功批次不重做，人工停止不自动重跑。
- 历史任务缺省仍为零，原冻结合同不改写；明确选择失败批次后开始新一轮最多三次自动重试，generation 保持递增。旧页面不能把上一代请求用于后来已失败的代次。
- 传输错误持久化在原批次，按 5 至 60 秒退避检查，不消耗重新分析次数；原 Session、消息和摘要保持。环境不可用期间暂停新模型派发，恢复后继续核对原身份。错误只保存安全分类，不保存原始 HTTP 响应、凭据或异常正文。
- 取消已知 Session 不再强依赖列表或状态读取；状态读取失败仍可请求独立 abort。缺少明确停止证明时保留 STOPPING、租约及后续检查。取消与执行 worker 串行，未知创建仍须精确身份核对。
- 历史环境等待提供按 Task 版本的“重新检查并恢复原批次”，保留原 Attempt、执行周期和累计预算；预算/时限或取消状态不能借此继续。失败清单始终可读，分别显示自动重试次数和传输检查次数，支持单批立即重查。
- V116 只追加批次重试策略及传输故障表。升级保留旧合同、会话、消息身份和结果；删除与回滚保留外键一致性。
