# 0.3.96：20 秒故事统计全流程验证与取消竞态修复

## 范围与根因

在 0.3.95 的统计交接顺序和源项目 Git ignore 修复基础上，以真实 OpenCode、原生工具、本地模型和独立统计接收端执行首轮 21 项场景。start、continue、complete 每次实际等待 20 秒；降级场景模拟已有故事、start 明确失败后 continue 成功。全部首轮场景执行完毕后集中修改生产代码。另以保留的 0.3.95 基线补验原截图中的范围外修改确认／取消两项路径，最终统一回归共 23 项。

确认并修复两个产品缺陷：

1. **统计等待结束后迟发已停止的业务提示。** 普通 abort 与统计命令已协调，但 `prompt_async` 不在同一交接范围中。停止设计师时 abort 等待 start 返回，旧业务线程随后仍可能发出提问，导致已取消设计出现未结束的问题，后续 complete 卡住。现在业务提示在等待前保存 Session 停止修订，普通停止使已经等待的提示失效；实际投递与 abort 串行。取消单次统计仍继续业务，显式恢复的新提示仍有效。
2. **同一执行轮次重复冻结工作区。** 正常收尾和取消后的租约协调能同时读到 CAPTURING。即使 Git 命令串行，第二个调用仍再次执行冻结，之后将已经 READY 的检查点当失败处理，返回 `WORKSPACE_CHECKPOINT cannot apply FAIL from READY`。现在按执行轮次共享整个捕获流程和结果，包括数据库意图、Git 操作、READY 落库；旧 freeze 不重新捕获已结束的检查点。

新增两个最小复现测试：`OpenCodeBusinessPromptCancellationTest` 和 `TaskWorkspaceCheckpointConcurrencyTest`。两者在修改生产代码前均实际失败，其中检查点测试复现与原生链路完全相同的异常；集中修复后通过。

首轮也发现并校正测试夹具问题：后台收集的稳定等待窗口、从统计记录提取尚未回填到 Designer 的 Task ID、使用合法的 REVISE 评审结果、用无变更触发验证失败、通过正式重做入口派生已结束任务、暂停恢复产生第二次 Attempt，以及浏览器先前未结束统计的选择。原始失败证据保留，不计作产品缺陷。首轮及补充场景的完整诊断结果见最终矩阵记录。

## 验证

- 聚焦及受影响集成回归：36 项，失败 0、错误 0、跳过 0。覆盖两个新复现、统计调用/取消/重试、首次任务交接和 Recovery。
- 完整门禁：`./scripts/verify.sh` 成功，Java 1590 项，失败 0、错误 0、跳过 2；Vitest 43 个文件、319 项全部通过。工具和原生 guard 检查通过。
- 正式 JAR 的 23 项原生 20 秒回归：22 项通过，1 项失败；此版本仅为诊断候选，未作为最终交付。失败场景为执行者 start 等待期间取消任务，取消接口返回 `SESSION_VERSION_CONFLICT`。数据库审计证明用户取消与后台 STOPPING 收尾同时持有旧 Session 版本；Session 最终 ABORTED、Task 最终 CANCELLED，但重复写入使用户收到 HTTP 409。
- 同类暂停补充测试还复现 `EXECUTION_SESSION cannot apply UNKNOWN from FAILED to ABORTED`：已被暂停拦截的提示被提前记为业务失败。这两个停止流程问题继续在 0.3.97 集中修复并统一回归，见 [后续交付记录](0.3.97.md)。

场景包括正常开启、失败后 continue、设计师和执行者三个操作分别取消、停止设计、任务开始/结束统计时取消、失败或取消后的统计重试、重复点击重试、验证失败后的重新执行、双评审重试、重做、暂停恢复、交接期间取消、浏览器取消/关闭/刷新，以及进程中断后的 UNKNOWN 恢复。成功任务逐项核对双 Judge PASS、普通场景的持久化差异只有 `config.properties`、实际补丁从 false 改成 true，忽略的插件运行文件不出现在范围外确认中；主动制造的 notes.properties 范围外修改必须逐文件确认。

复现入口和环境要求见 [统计合同](../story-binding.md)。原生接收端和模型均只使用本地端口，未调用真实内网统计系统或付费模型。过程日志保存在本次隔离目录及 `/tmp/loopper-story-*.log`，不写入业务数据库作为修复方式。
