## 范围与现场结论

Linux 现场的 `rev-parse --is-inside-work-tree --show-toplevel HEAD --abbrev-ref HEAD` 已成功，且 `cms` 与返回仓库根目录一致。本次截图不能归因于 Git 未安装、HTTP clone 丢失 Git 元数据或该路径是子目录。

同一用户执行非交互 `ls-remote` 后返回 `could not read Username ... terminal prompts disabled`，证明该调用未获得可用的 HTTP 用户名凭据。IDEA 克隆时可用的凭据没有在这次系统 Git 调用中生效。现场旧任务的通用超时没有操作名，不能仅凭此证明超时发生于远程查询；本地全历史快照也有自己的超时。

## 修改

- 保留子目录登记、执行目录和文件验收范围；项目读模型显示实际所属 Git 仓库。
- 同一 checkout 的子项目共用 FIFO 写租约与分支。历史目录队列保持冻结身份，重叠旧租约阻断新写入；应用私有报告目录不参与源码目录的重叠判断，停止证明及恢复边界不变。
- 脏文件、检查点、只读快照、差异验收和提交按项目路径处理；兄弟目录变更（含暂存区与工作区相互抵消的情况）阻断处理，不能被子项目提交或清理。
- 模板历史采集、冻结版本审查与需求代码快照从实际仓库获取对象，只暴露项目范围。日期边界没有该子目录时使用空树。已有已冻结快照保持原范围。
- 明确选择本地分支后，确认过程不再重新访问远程。远程认证失败与查询超时保留本地选项，页面显示安全分类原因。超时信息附操作名和时限，不暴露 URL、凭据或原始 stderr。

- 设置页提供全局 Git 默认账号，项目默认继承，可配置独立账号或恢复继承；仅 Loopper 管理，不修改系统 Git 配置。支持密码/Token、AES-GCM 加密保存、版本冲突和只读连接验证。远程分支、fetch 与正式 push 按项目选择账号，私有快照携带原项目身份。凭据按服务器来源隔离，不允许重定向携带凭据。
