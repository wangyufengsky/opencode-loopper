# 0.4.43 本地交付：知识库默认模型与重新读取修复

日期：2026-09-17。基线：0.4.42 / `01ec212`。本次仅本地交付。

## 原因与修复

设置接口分别返回 `openCode.provider`、`openCode.model`，可用模型目录及知识库创建接口使用完整的 `provider/model` 标识。知识库页面此前只读取裸模型名，导致默认选择与目录不匹配，创建会话被服务端拒绝。原有浏览器夹具把完整标识误放进设置的 `model` 字段，未覆盖真实接口形状。

- 新对话从设置的提供方和模型名组装完整标识；同名模型不跨提供方猜测。服务端原有精确模型校验保持。
- 模型不在目录、模型配置读取失败或正在重新读取时阻止新对话发送，并保留恢复入口。
- “重新读取”真正刷新设置及模型目录，保留问题草稿、手动选择和创建幂等身份；已有会话继续使用冻结模型。
- 更新浏览器夹具为真实设置形状，并增加通过真实 API client 归一化逻辑的组件回归。合同同步于 [项目知识库合同](../knowledge-contract.md)。无新增迁移或 Java 行为变更。
