# 0.4.29：提交合同查询与批次恢复

## 范围

- 增加统一 `describe_submission_contract(runId, pointer)`，返回当前角色实际注册的提交 Schema、必填字段、枚举、当前修订号及填写提示；支持按 JSON Pointer 查询子结构。身份、冻结作用域和运行状态沿用正式提交校验。参数查询不产生业务接受或消耗候选提交次数。
- 增加需求评审工作目录 `get_document_review_work`、候选预检 `check_document_review_candidate`，以及需求开发的 `get_development_task_guide`。模型可查分段标题、已有需求和当前阶段交付物/路径；预检失败提供修正反馈，正式提交仍须独立验证。
- 新版文档候选允许 `snapshotSha=null` 由服务端绑定本次冻结 SHA；显式错误 SHA 和代码 blob 引用仍拒绝。历史输入保持旧校验边界，未取得实际读取证据不得通过。
- 第一期模板版本 9 和需求代码评审版本 3 按逻辑批次独立自动重试，最多两次；已完成批次保留，其他独立批次继续占用并发窗口。耗尽后分页展示失败批次，用户每次点击只创建一个新尝试；重复请求返回同一个新批次。
- 新增 V109，保留旧批次、Session、提交回执、续写及错误记录。手动恢复不清零任务总预算或时限，也不跳过停止证明。历史第一期失败任务支持显式批次续试；历史文档版本 1/2 仍沿原恢复入口。
- 并发窗口仍默认 4、可在设置中调整，需求开发保持单写入执行。报告须等所有批次完成并通过既有验证，失败和未知结果不能成为“全部满足”。
