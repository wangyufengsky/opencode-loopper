# 代码快照审查轻量策略研究

研究日期：2026-09-16。用户目标：周度增量审查采用统一轻量策略，减少大量规划、分析和复核 Session。本文是外部一手资料形成的设计建议，**不代表本项目已实现或已取得相同质量、耗时结果**；具体实现与验证由对应交付记录说明。

## 建议的固定流程

冻结差异 → 程序按容量分批 → 每批一次审查 → 合并候选问题 → 仅对实际候选问题进行一次集中复核 → 程序汇总报告。

取消模型前置分组、全量无问题结论复核、每条功能关系单独开 Session，以及模型递归追加补充批次。允许审查 Session 在现有冻结快照范围内按需读取调用方、实现和测试；证据不足就记录限制，不扩展成新的审查流程。该流程是本项目的设计建议，外部来源只支持其中的原则与实践。

## 一手证据与取舍

| 设计选择 | 一手证据 | 本项目建议与限制 |
| --- | --- | --- |
| 取消 LLM 前置规划 | Anthropic 建议先用最简单可行方案；多步代理通常增加延迟和成本，只有可测收益才应增加复杂度。[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) | 差异、路径和大小已经确定，可用程序稳定装批。模块/目录只是优先邻接规则，不再花一轮模型调用生成分组。可能减少语义分组精度，需要用跨文件缺陷样本检验。 |
| 按材料容量合并 diff | PR-Agent 按 token 预算拟合补丁，并在大型 PR 中分块；`improve` 文档明确分块随容量发生，通常无需每个小片段单独调用。[Compression strategy](https://docs.pr-agent.ai/core-abilities/compression_strategy/)、[Improve](https://docs.pr-agent.ai/tools/improve/) | 文件头附着实际变更，优先保持同文件与相邻模块；同时计算提示、差异、输出和工具上下文预算。不能照搬其删除片段压缩策略：删除代码也可能引入回归，未送审材料必须显式记录。 |
| 只复核实际候选问题 | Anthropic 官方 code-review 命令在检测之后，仅为已发现的问题启动验证并过滤未验证问题；同时要求同一问题只输出一次。[当前命令源码](https://github.com/anthropics/claude-code/blob/main/plugins/code-review/commands/code-review.md) | 使用一次或少数容量受限的复核批次核验合并后的 findings，不让每条 finding 再独立产生 Session。该插件整体仍是多代理流程，这里只借鉴验证对象。无发现批次将失去第二遍独立搜索，不能声称召回率不变。 |
| 保留按需读取关联代码 | Anthropic 介绍预置有限上下文与 just-in-time 工具检索的混合方式，并指出过多上下文和无目的探索都会降低效率。[Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | 首次给完整批次 diff、变更文件索引和精简项目约束；仅围绕具体调用、数据和权限假设读取关联内容。不能把“轻量”变成禁止读上下文，否则容易把上下文解释得通的代码误报为缺陷。 |
| 不递归补充、显式收尾 | Anthropic 将最大迭代次数列为控制代理运行的停止条件，并要求评估额外步骤是否改善结果。[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) | 固定一轮发现、一轮候选复核；预算耗尽返回证据不足/未覆盖清单。同会话协议修正、冻结预算和停止证明沿用既有合同，不把纠正通道变成递归补充分析。此处“一轮”是本项目成本目标推导，外部资料没有验证其适合所有仓库。 |

## 轻量审查的内容范围

- 报告能说明触发条件、错误结果和证据位置的实际缺陷，包括业务错误、权限绕过、数据损坏、并发与资源问题。
- 不为风格、命名偏好、泛泛重构建议或“也许值得补测试”制造候选问题。
- 同一根因先合并后复核；复核只判定候选成立、误报或证据不足，不承担新一轮全面搜索。
- “没有确认问题”与“保证没有问题”区分；未读取、被排除和超限材料在报告中可见。

不照搬 Anthropic 示例中“不报告依赖特定输入或状态的问题”的宽泛过滤：业务和并发缺陷通常依赖具体输入或状态，只要能提供可验证触发路径，就应保留。

## 本地验证指标

Session 数应主要由输入材料容量和实际问题量决定。令 `B` 为装批后的审查批数，`V` 为候选复核批数，则正常模型 Session 数约为 `B + V`；无候选时 `V = 0`。这是一条设计目标，不是当前实现测量。

在同一批固定快照上比较旧流程与新流程：模型 Session 数、输入/输出 token、总耗时、重复读取量、确认缺陷数、误报数及已知缺陷漏报。至少包含跨文件调用、删除代码、权限、事务/并发、大文件和大量小片段。冻结身份、覆盖校验、恢复和协议测试可以先用合成夹具；审查质量必须另用真实模型及已知缺陷样本验证。

**不直接采用外部工具的 token、行数、置信分或候选数量默认值。** 批次容量、工具读取预算和复核合并大小需结合实际 Provider 上下文与本地样本确定；在完成这些测量前，不承诺固定降幅、一天完成或质量等价。
