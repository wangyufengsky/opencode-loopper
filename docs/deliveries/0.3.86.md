# 0.3.86 — Designer 确认与 LoopSpec 无损往返修复

## 问题与范围

2026-09-08，CupXml2Java 文档设计已处于 FINAL_REVIEW / DRAFT_READY，服务端 finalConfirmationEligible 为 true，但点击确认后的保存前校验出现一项阻断。

对当前草稿执行不落库的校验对照：完整持久化 LoopSpec 为 valid=true；模拟旧前端序列化后为 valid=false，错误为 `stages[0].verifiers[0].documentAssertions: DOCUMENT_STRUCTURE requires bounded assertions`。确认按钮触发的请求漏传了文档断言，并非缺少确认权限。

本次按用户要求检查同类缺陷，覆盖领域 LoopSpec 与前端读取、编辑、创建、校验、保存之间的字段映射及全部 13 类验收器。

## 修复

- 保留 DOCUMENT_STRUCTURE.documentAssertions、TABULAR_DATA.tabularAssertions，以及 Stage 的 stageKind、executionStrategy、artifactPlanId；继续保留 workPackageId、验收映射、模型、预算和会话策略。
- 补齐文档／表格验收类型选项、目标路径和结构化断言控件；断言数量与数值上限对应现有服务端 DTO。
- 显式切换验收器类型时，移除新类型不适用的旧字段，避免 PROCESS.outputContains 等不可见残留继续阻断确认；保留 criterionIds。普通读取不执行该清理。
- 缺少断言的错误指出阶段、验收器和补充动作；多项错误同时保留。
- 未知的阶段类型、执行方式、实施类型、验收方式、命令用途及运行时就绪匹配方式不再静默丢弃或改成默认值，直接阻断读取并提示升级。
- 时长输入支持整数秒、整数天／小时／分钟／秒组成的 ISO-8601 时长及首尾空白；无效格式在发送前报错，不替换成默认值。精确文本、空字符串、0、false 的往返纳入回归。
