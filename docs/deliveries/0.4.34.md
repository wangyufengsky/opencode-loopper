# 0.4.34：模板批次收尾、停滞诊断与单批恢复

## 交付范围

本次针对“候选已 ACCEPTED，OpenCode 仍 busy，批次长期 RUNNING”的故障，按优先级实现以下五项。

1. **接受后的收尾。** 以持久化接受时间为基准保留 60 秒正常结束窗口；超出窗口后只停止精确绑定的会话，复用已接受结果完成批次。历史挂起批次不用重新分析。
2. **停止与结果分开。** 收尾意图、命令及停止证明持久化。只有远端独立终态、明确 abort 确认或精确不存在才能完成；停止结果未知时保留结果和占用，停止请求重试至少间隔 15 秒。取消优先，迟到回执不能复活取消任务。
3. **真实进度诊断。** 分开显示最后检查、内容活动、候选进展、接受和停止时间。五分钟无新内容标记疑似停滞，90 秒无有效观察提示连接未确认；不据此自动中止未交卷模型。内容摘要在展示裁剪前生成。
4. **单批恢复。** 已接受批次提供“结束会话并收尾”，未接受批次提供“停止此批次”。按版本、当前代次和命令幂等校验；停止意图提交后禁止新候选和长度续接，停止确认后按既有批次重试流程处理，不重跑成功批次。
5. **可操作的诊断入口。** 任务页面提供需要关注、未完成、全部批次及服务端游标分页；按需展开本地/远端会话标识、目录和回执信息，可复制不含认证凭据或模型正文的摘要。无需直接登录受控 OpenCode。

规范：[模板批次收尾与诊断](../seven-feature-contract.md#模板批次收尾与诊断)。V111 追加三张表，不改写历史迁移或冻结任务合同。

本次不开放原会话任意追加消息，不自动重跑整项任务，不增加未接受候选的业务总超时。诊断时间表示实际观察，不能证明模型正在推理。模拟客户端和浏览器夹具验证协议及恢复行为，不代表内网真实 Provider 已验证。

本次交付为本地提交、完整 JAR 和本地服务更新；不包含远端推送、标签、Release 或内网机器部署。截图中的内网故障会话是否恢复仍需在该环境确认。
