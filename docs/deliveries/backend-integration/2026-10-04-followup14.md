## 唯一生产行为修复

[SafeProcessRunner](../../../src/main/java/io/opencode/loopper/runtime/SafeProcessRunner.java) 原先强杀所有 descendants 后立即强杀 direct parent。现在仅处理自身快照树：按父链深度从叶到根终止，在**共享总500ms轮询预算**内保留父进程回收机会，再 finally 结束自己的 direct Process。callback/timeout 以同一个 Process monitor 串行；deadline 在获取 monitor 前确定，枚举与排序异常也进入 finally；中断仍发送剩余终止请求并恢复 interrupt flag。

没有使用 descendant `onExit()`：锁定 JDK21 对非直属 child 的异步 reaper 可能在僵尸状态持续等待，caller 超时不会自动释放该等待。没有修改 `DurableCommandProtocol.Identity`、command receipt、stop proof、Git scope、租约策略或原测试；没有操作 PID1、其他进程、全局监听或依赖私有状态。

新增 [SafeProcessRunnerTreeTest](../../../src/test/java/io/opencode/loopper/runtime/SafeProcessRunnerTreeTest.java) 两项真实三层 Java 进程树：output overflow 和 timeout。overflow 必须 `outputTruncated=true` 且 `timedOut=false`，排除靠 timeout 兜底；两层 descendant 仍使用2秒原生 ProcessHandle 判活门槛。

**限制**：500ms约束等待，不是 monitor获取、枚举或 native signal 的硬墙钟上界；快照不承诺捕获之后新 fork 的全部进程。`ManagedProcess.stop` 与 run 外层 interrupt 清理原样，未宣布它们全故障通过。故意杀 supervisor 产生的孤儿僵尸不在此次正常 runner 修复内。
