# 0.3.94 候选修正边界与任务提交校验

## 变更

- 将候选拒绝与停止修正分开：候选的服务端专属字段、Judge 候选角色/版本、Reviewer 路径及设计范围错误继续拒绝，但允许同会话完整修正；真实运行身份、冻结证据、停止证明和预算限制不变。
- 普通单包语义范围不再使用 Java 默认目录作为用户允许路径白名单，支持项目内资源、配置、多模块和新建目录。明确文件范围与原文“只修改”等限制继续校验；增加 `.git` 与嵌套环境文件保护，系统保护作为目录范围中的排除项，保留原有精确文件/目录类型语义。
- 拆包缺口和多任务声明须由原文支持，已委托设计师的选择不再要求用户重新决定；旧编译流程允许对必改路径未归属继续自动重设计。
- 人工恢复当前包设计不再被自动重设计次数挡住，保留总调用预算和冻结身份检查。
- 编译结果缺失验收器或安全约束归为内部故障；显示精确路径、实际/预期和恢复要求，不把编译器故障说成需求缺失。
- 提交说明的 AI 生成、标题兜底、手工编辑、预览与提交统一单行规范化；服务端独立校验工单号、空值、120字符上限及控制字符。用户说明超限不截断，AI 生成失败时界面如实显示标题兜底来源。
