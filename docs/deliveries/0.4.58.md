# 0.4.58 暂停自动自查并修复 Windows OpenCode 启动

按用户要求，暂停知识问答在模型回答结束后自动补发自查和 Todo 续查 prompt。模型本次生成正常结束并返回非空答案后，服务端直接完成这一轮；不因 Todo 为空、未完成、截断或不可用而追加请求。

初始提示中查清问题、自主连续调查的要求，以及 MCP 软优先级、原生只读工具、工具记录和引用能力保持。模型仍可在一次生成内多次调用工具，用户可以正常继续提问。

保留 V118 及历史续查数据。升级前已持久化的请求按原身份恢复，投递未知不重发，停止仍要求正向证明；历史请求完成后不再创建下一轮。删除新续查创建逻辑和自查 prompt 模板，不增加配置开关或新的数据库迁移。

同时处理任务“排查 Windows OpenCode 启动失败”中确认的问题：托管启动原先按大写 `PATH` 查找且可能优先选中无扩展名 Unix 脚本，模型发现则使用 Windows 扩展名解析，造成能发现模型却无法启动。托管启动现复用 `ExecutableResolver` 的 Windows `Path` / `PATHEXT` 规则，支持 `.exe`、`.cmd` 及带空格的完整路径。运行页面将“未找到启动文件”的原始错误显示为明确中文恢复说明，不再把环境变量名误当错误码显示为“未知”。保存配置后的显式启动重试和进程所有权边界保持。
