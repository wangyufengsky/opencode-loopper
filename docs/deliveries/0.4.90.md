# 0.4.90 Windows 全量回归修正

## 范围与发现

继承 [0.4.88 流程功能](0.4.88.md) 和 [0.4.89 的 Windows 夹具修正](0.4.89.md)。0.4.89 尚未发布，扩大 Windows 验证后发现额外产品问题，按候选版本规则顺延为 0.4.90。

- 项目取消管理后重新注册，可能读取旧的技术栈画像。旧查询依赖时间字符串和随机 ID 排序；相同时间、不同时间精度都不能可靠表示保存顺序。V191 追加画像顺序字段和索引，在 INSERT 内分配顺序号，详情及列表统一读取最新已保存画像。历史画像正文、ID 和冻结引用保持，V42 等旧迁移不修改。
- 源码分批的目录标题原先通过宿主 Path 转换，Windows 将固定清单的 `src/feature` 变成 `src\feature`。改为直接划分固定清单的 `/` 路径，同一清单生成一致的目录标题，覆盖范围和文件顺序不变。
- Windows runner 的进程启动异常仍在独立诊断中；不能把 JVM 分类隔离当作已验证的基础设施修复。

## 已取得的证据

- Windows 2022 原生对照 `36672215117` 的两种 JVM 模式均复现项目重新注册读取旧画像；复用 JVM 的 59 类/344 项测试完成，唯一断言失败是这一问题，4 项原有条件跳过。
- 本地确定性红灯 `ProjectStackProfileServiceTest`：7 项中 3 项失败，三个时间/ID 边界均在画像详情与项目列表复现旧结果。
- 修复后项目画像、迁移、分析器、路由和项目控制器聚焦：49 项，48 通过、1 项原有条件跳过、0 失败/错误。V190→V191 文件数据库升级、历史组件引用与 VACUUM 后顺序验证通过。
- Windows 分组 `36671200542` 的第 2 组完整执行 59 类/436 项，唯一失败为源码分批标题的路径分隔符；已保存完整 Surefire 附件。
- 修复后 `SourceDesignBatchesTest` 与 `WorkflowSourceDesignIntegrationTest` 本地 26 项全部通过；结构、旧设计模板和原生单测流程受影响集成 43 项，39 通过、4 项原有外部环境条件跳过。
- 原生 Windows 修正验证 `36673642495` 全部成功：Windows latest 和 Windows 2022 各执行 7 个测试类、68 项测试，0 失败/错误/跳过。两种镜像也各完成 300 次 Java 和 300 次 CMD 独立启动对照；这没有复现整体测试运行中的进程初始化错误。
- 正式 Windows CI 改为动态发现测试的 8 个分组，沿用 Maven 默认 JVM 复用。每组完整构建及前端验证，最终要求同一提交的全部 483 个 Java 测试类完整且无重叠。覆盖守卫的缺失、重复、混合候选和失败结果回归通过。临时固定清单与诊断工作流已移出正式代码，保留在忽略的诊断证据目录。
