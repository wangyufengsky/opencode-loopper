## 目标与完成定义

将 Loopper 从固定业务流程组织方式演进为可配置、可创作、可执行、可在运行中修订的流程体系。
先完成前端生图设计，再完成基础模块化，最后实现新功能。每个阶段有可核查产物，完整目标不能以效果图、空接口或单纯配置目录代替。

最终用户能够：
- 在“流程”中查看内置及自定义模板，创建、复制、编辑和删除自定义模板。
- 从“需求任务”选择流程，进入本次需求的规划画布，调整节点后开始。
- 自由拖动、缩放、连接、增删改节点；图形位置与执行依赖分开。
- 组合预设工作模块及自由任务，选择角色、输入来源、交付物与完成标准。
- 单步执行、执行到选中节点、连续执行、设置人工检查点、暂停后续调度。
- 使用前置节点的版本化交付物继续工作；支持多个前置依赖、条件分支、并行和汇合。
- 查看设计/规划节点生成的候选计划，编辑或确认后使后续计划生效。
- 在重试耗尽后保留现场，修改、重试、替换或移除失败节点后恢复。
- 按自定义完成策略结束；人工认定成功、失败或取消，并独立选择提交成果。
- 在画布中查看节点实际运行、输入输出、模型活动、历史尝试和恢复入口。
- 通过默认开发流程承接原设计工作台，取消新建大型任务与需求开发模板的重复入口；其他内置模板也变为可配置流程。
- 继续读取和恢复历史任务，沿用它们冻结的角色、权限、验收和执行合同。

## 用户已确定的决定

1. AI 生成的新增、删除、调整后续节点均先展示给用户，确认后生效；连续执行同样遵守。
2. 自定义流程可取消开发后审查，业务测试、评审与验收由用户定义；不得在后台补上已删除节点。
3. 预设模块和自由填写任务第一版同时提供，使用同一节点合同。
4. 节点成功需要交付物，允许结构化数据、文档、代码快照、判断结果或系统控制记录。
5. AI 优先通过 MCP 向程序提交，SQLite 持有身份、版本、内容/文件清单与输入血缘。
6. 本次任务计划独立于模板；模板修改不改变已有任务。
7. 已发生执行与交付物保留历史；删除指移出有效计划，不抹除既有事实。
8. 普通程序完整性、路径/权限、停止证明、幂等守卫保留；自定义完成规则不扩大文件或工具权限。
9. 用户直接编辑并应用视为确认；AI 候选必须明确显示“尚未生效”。
10. 完成、人工认定和成果提交是不同事实；连续执行不附带推送或发布授权。
11. 根据后续讨论，独立“流程规划师”不列为必做角色。流程规划是可复用工作能力，优先由现有设计师/任务规划师承担；已经有结构化阶段安排时由程序转换，不重复调用 AI。用户以后仍可配置专门规划角色。

## 阶段二：最基础的模块化改造

先完成一个有真实调用者、至少两类实际工作支撑的基础批次，避免只增加通用转发层。

### 2A：现有工作目录与执行合同梳理

- 梳理 Designer、Implementation、Judge、知识库、Git 报告、快照审查、文档模板、源码模板的角色调用、候选提交、停止、产物和恢复入口。
- 提取共享工作定义与目录，区分角色配置、工作模块、流程模板与运行实例。
- 现有页面和接口先使用新的共享目录；保持它们当前可观察行为。
- 对所有内置模板列明适配入口、输入来源、交付物、完成策略及历史版本规则。

### 2B：版本化交付物与输入解析

- 统一交付物元数据、不可变版本、生成节点/尝试、内容摘要和输入引用。
- 小型正文/结构化数据保存在 SQLite；大文件使用受管制品目录和持久化清单。
- 通过现有 MCP 候选接收结构接入统一交付物，不复制鉴权、幂等与候选语义。
- 先接入两类真实工作产物，证明不同调用者能共享身份、存储与读取规则。
- 提交接受、会话结束、节点完成分别记录。
- 前置输入按计划绑定解析成不可变执行快照；禁止自动采用“最新”版本。

### 2C：节点运行与旧能力适配

- 节点运行/尝试与模型 Session、旧 Task/Stage、Queue/Lease 保持独立身份。
- 封装启动、只读观察、停止、交付、重试所需的最小工作接口，复用现有协议与资源守卫。
- 只读节点可并发；共享代码目录的 writer 必须串行或通过受管隔离工作区合并。
- 至少一条既有实际流程通过共享模块运行并完成原回归；不以孤立新模块测试替代集成。
- 不提前启用新流程入口，不静默改动历史成功规则。

阶段验收：
- 聚焦测试与受影响集成回归；包含重复提交、版本冲突、跨作用域、迟到结果、停止未知、重启恢复、输入缺失。
- 新库和旧库升级路径通过；迁移只追加，序号在集成时复核。
- 真实调用者接线和原业务行为有证据，角色冻结版本与权限不扩张。
- 稳定候选按完整门禁、本地服务与提交规则交付。

## 阶段三：流程创作与流程规划新功能

### 3A：流程库和创作画布

- 内置/自定义目录、服务端分页/搜索、详情、版本、创建、复制、保存、删除。
- 共享画布：拖动、缩放、适配视图、自动布局、连线、增删改、撤销重做、只读预览。
- 预设模块/自由任务、节点输入输出绑定、条件连接、完成规则、人工检查点。
- 依赖环、悬空输入、重复标识、类型不匹配、权限不兼容等错误定位到具体节点。
- 内置流程可查看和复制；编辑自定义流程不改变已有实例。

### 3B：需求任务与执行画布

- 需求入口选择项目、资料和流程；保存独立计划版本。
- 确认计划与正式 Start 分开，持久化请求身份与幂等回执。
- 实现单步、运行至节点、连续、检查点、暂停派发和停止当前运行。
- 服务端按依赖、条件、并发资源及交付物可用性调度；界面只投影实际事实。
- 节点详情按需加载日志/正文、制品、输入血缘与历史尝试。

### 3C：失败、修改和恢复

- 区分业务结果“需要修复”和技术运行失败。
- 有界自动重试；耗尽后进入停滞且不再派发新节点。
- 修改未开始的后续节点；停止后的失败节点可修订/重试/替换。
- 上游版本改变会标记受影响的下游，不能自动给旧结果换输入版本。
- 删除/替换节点时检查所有消费者；终态历史与制品保留。
- 进程重启、网络断线、未知停止、并发确认和迟到事件均能恢复。

### 3D：规划能力与动态计划

- 为适用现有角色提供“生成候选流程计划”工作模块及专用 MCP 候选合同，不强制新增角色或独立规划节点。
- 设计节点可同时交付设计方案与候选计划；结构化阶段安排优先确定性转换，避免重复模型调用。
- 候选计划绑定基准版本、可修改区域及输入成果，不自动生效。
- 画布展示新增/修改/删除差异；用户编辑、退回、确认。
- 确认 CAS 验证当前计划及执行状态，原子切换未开始部分；完成/运行中历史不能被改写。
- 按已确认的节点继续执行；规划候选自身也是可追溯交付物。

### 3E：迁移现有入口与内置流程

- 默认开发流程承接需求澄清、设计、开发与原默认验收节点。
- 需求任务承接原设计工作台入口；取消新建大型任务和需求开发模板的重复入口。
- 将历史提交审查、代码审查、贡献周报、需求代码评审、单测开发、详细设计编写逐一转为内置流程。
- 自定义流程按自身完成规则执行，不继承隐藏的固定双 Judge 步骤。
- 旧 Task/Designer/Template/Recovery 保持原合同恢复；新旧界面互链，不破坏历史证据。

### 3F：整体验收与交付

- 浏览器实走三条路径：自定义轻量开发无审查、带审查/修复分支、知识检索到文档交付。
- 覆盖规划确认、改后续节点、失败恢复、并发汇合、取消与人工提前结束。
- 核对全部内置流程、旧任务升级/恢复、交付物来源、角色/权限冻结。
- 聚焦/受影响集成稳定后一次完整门禁；构建后可执行内容再变则分配新版本。
- JAR/static/SHA、运行实例归属、数据备份、正常停止、启动器更新、健康/版本/PID、浏览器与适用 Provider 验收分别留证。
- 更新交付记录并仅提交本任务内容；未经授权不推送、不创建 PR、不发布标签/Release。
