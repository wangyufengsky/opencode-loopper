# 0.4.44 本地交付：知识库辅助 MCP 授权修复

日期：2026-09-17。基线：0.4.43 / `3c17ac2`。本次仅本地交付。

## 原因与修复

用户实际知识库回答出现 `ASSIST_SCOPE_DENIED`。只读检查确认该会话已建立远端 Session，但 `assist_session` 和辅助 scope 所有者绑定均缺失，知识工具记录为 0。首次精确创建的 HTTP 路径只登记运行身份，辅助权限快照仅在精确恢复路径登记；发送前又把空 grant 当作“无辅助能力”静默略过，导致模型拿不到有效工具凭证。

- 首次创建与精确恢复共用 `validateOrRegisterBinding`，在返回远端 Session 前登记运行身份及冻结辅助权限。
- 知识问题传输前必须获得有效 grant，且持久化角色必须为 `KNOWLEDGE_READ_ONLY`。缺失授权时在模型 POST 前明确拒绝。
- 仅对明确发生在 POST 前的 `ASSIST_SCOPE_UNAVAILABLE` / `ASSIST_MCP_UNAVAILABLE`，将回合从 SENDING 标记为 FAILED，并释放会话以供用户操作。实际网络投递未知仍保持 UNKNOWN 和原有精确查询恢复，不推定未发送，不自动重投。
- 没有放宽 MCP bearer、代次、会话所有者、工具白名单、目录或资料范围。未修改历史消息和已有迁移。
- 同步 [知识库合同](../knowledge-contract.md) 与 [辅助 MCP 合同](../assist-mcp-contract.md)。旧运行代次的会话不冒充新代次授权；历史继续可读，更新后通过新对话建立有效授权。
