# 冻结版本代码审查合同

本合同持有 `SNAPSHOT_CODE_REVIEW` 的行为。新建任务统一使用版本 3 轻量策略，日期增量和全面审查不提供额外重型策略开关；版本 1、2 仅用于已有冻结任务恢复。它与 `CODE_REVIEW` 历史提交审查、贡献周报、需求代码评审分别冻结合同。公共入口、报告路径、幂等确认与正式 Start 沿用[模板任务合同](seven-feature-contract.md#内置模板任务)，冻结版本审查由独立协调器执行，不采用历史模板的逐提交编排。

## 输入与版本

- 目录声明 `DATE_INCREMENTAL` 与 `FULL`；默认日期增量。全面审查请求不携带日期。
- 日期按北京时间 `[开始日 00:00，结束日次日 00:00)` 解析，结束当天包含在范围内。首次执行在任务自有 bare 仓库冻结所选分支来源 SHA。
- 增量完整遍历来源 SHA 的第一父链，按从新到旧拓扑顺序分别选择 committer 时间严格小于两个边界的第一个提交。时间倒序不提前剪断，记录异常。该规则推算当前主线历史，不能证明当时分支位置或部署状态。
- 冻结来源、基线、目标、树、时间范围、选择依据和采集时间。结束时间尚未来临时只覆盖已采集历史，不等待或监控未来提交。恢复与重试不重解日期和分支。
- 无边界版本、浅历史、历史数量或单次输出超限，在模型调用前阻断；不退回全面审查。沿用 Git 2.30.2 能力与采集停止证明。
- 增量比较最终树，支持新增、删除、重命名、模式变化；同 SHA 或不同 SHA 同树均不调用模型。全面审查列出冻结 tip 的目标文件。
- 登记项目为仓库子目录时，来源和日期边界仍使用仓库提交 SHA，文件清单与差异只取该项目子树，路径相对于项目目录；日期边界尚不存在的项目子树按空树比较。新快照冻结项目相对路径，已有快照按其原范围恢复，不因升级扩大或缩小历史审查范围。

## 证据与权限

角色只能通过专用 MCP 查看冻结目录、分段代码、单文件检索、工作目录、功能组和同任务已接受批次；结构化提交复用版本校验、幂等回执和同会话修正通道。任务、批次、Attempt、Session、托管运行代次、SHA 与 blob 均须匹配。用户 MCP、项目命令、原生文件读取、编辑和 question 不开放。仓库文本不能改变这些权限。

共享 `DocumentCodeContentCache` 的底层代码缓存按任务、SHA、blob 隔离，缓存命中后仍写当前角色读取凭据。一次最多读取 200 行、32,000 字符，V1/V2 每批最多 2,048 个不同读取片段；V3 另见关联读取边界。搜索不是读取凭据。V1/V2 引用须匹配本角色实际读取的版本、文件、blob、完整行范围和原文；当前缺陷须含目标证据。删除问题可以同时引用基线删除位置与目标残留调用。

敏感文件、符号链接、子模块、二进制/非 UTF-8 文件及默认第三方产物目录保留排除或局限；不跟随链接，不运行过滤器。配置、迁移、构建和启动源码在可读范围内照常审查。未知语言可做文本检查，但不宣称语法或跨语言调用图完整。本轮不运行目标项目的构建、测试或脚本，不自动修改代码。

## 版本 3 证据减负与阶段报告

V3 沿用 V2 的容量分批与问题复核流程，批次冻结 `LIGHTWEIGHT_V3`；不增加任务 Token、费用或耗时硬预算，模型及已有预算轴不变。不修改既有冻结合同、快照、批次或 Session，也不自动重启已取消任务。

- **初始证据直接引用**：冻结时把实际交付的完整 diff/文件行映射到版本、路径、blob 和行号，并与原始 blob 校验。只授予本批实际交付的代码；差异前缀不属于原文，跨 hunk/分片位置保持。提示仅附定位元数据，不重复附加同一份代码。模型可直接引用这些行，也可引用本角色的 MCP 读取凭据；不会因其他角色读过而获得额外证据。超长行的字符片段不能冒充完整行引用。
- **无问题简写**：coverage 仍须恰好覆盖全部分配单元，结论最多 160 字，通常一句话、`evidence=[]`，不要求逐函数长篇证明。缺少完整可引用初始代码时仍需实际补读或明确局限。候选缺陷、归因与独立复核保持原有证据校验，当前缺陷仍须目标版本代码。
- **关联读取边界**：每个 V3 批次最多 12 个不同的目录、单文件搜索或代码读取请求；同参数重放不重复计数，计数按批次持久化并原子占位，重启不能重置。一次最多 200 行、32,000 字符，分页最多 100 项；不遍历其他分组和任务结果，只可读取分配的分析依赖。达到边界返回明确诊断，要求使用已交付证据提交、把缺口写入局限，不伪造无问题结论。这是关联上下文范围约束，不是任务调用、Token、费用或耗时预算。
- **阶段报告**：快照冻结后可按需查看、刷新及下载 Markdown。运行中、失败或取消后均可读取，只纳入当前 Attempt/代次已 `VALIDATED` 的分析和复核，保留候选证据与引用。尚未收尾的 accepted candidate 不计完成；区分已分析、未完成、排除、未复核候选、独立支持、不成立、待确认与重复。只读生成，不改变 Task/Stage/Session 或完整报告的验收事实，兼容读取 V1/V2 已保存结果。报告正文不进入 overview/SSE，切换任务丢弃迟到响应。
- **后续审查复用**：首版保守复用 V3 中无候选问题、无局限、没有额外 coverage 引用的完整分析；来源必须已校验且 Session 已完成。本项目的规范路径与子目录范围、规则版本、模型、初始材料，以及完整基线/目标项目树都必须相同。比较树和 blob 而非提交日期，新的同树提交可以复用；引用的单元编号重新绑定到本轮，程序记录来源任务/批次和结果哈希，命中不创建模型会话。任意项目树变化（含调用方、配置、新增/删除与搜索未命中的依赖）、范围或模型变化都失效；源结果删除或哈希不符不可命中。返修、重试和资格验收绕过复用，不追认 V1/V2 结果。

上述复用是保守的第一版，不是只按代码文字或文件 hash 跳过检查。当前不具备全语言依赖闭包，因此不能安全复用“本段未改、其他依赖已变”的无问题结论；连续周审的实际命中率取决于冻结项目树与范围重叠，不承诺固定 Token 节省比例。阶段报告也明确无问题结果未经独立复核。

V113 仅追加关联读取请求、可复用结果索引及来源记录；删除 Task 时显式清理并保留外键约束。缓存索引不是业务成功状态，复用仍通过既有批次生命周期的 PREPARED → VALIDATED 入口及审计。

## 版本 2 轻量策略

流程为准备范围、代码分析、问题复核与报告。内部保留冻结证据、程序分批、分析、报告四个持久化阶段，前两个合并展示；程序分批不创建模型会话。

- **准备范围**：同文件的小型 diff hunk、类型和函数合并为有界代码片段，文件头附着正文。超大文件继续分段，原文、删除内容及续接位置保留；不按 hunk 或函数数量创建 Session。被保护、不可读取或第三方产物等排除项保留清单和原因，由程序记录，无需模型确认排除。
- **程序分批**：按稳定文件路径排序，同文件片段保持源顺序；每批初始代码材料最多 48,000 字符、64 个片段。容量是本版冻结策略，不代表 Provider token 上限。程序保存一次完整分批计划，不调用 PLAN/LINKS 模型，不生成逐关系任务。可读的超长行片段即使带续接局限仍必须进入分析。
- **一轮分析**：覆盖本批全部片段，使用简短结论和真实引用。聚焦有具体触发条件、错误行为和代码证据的缺陷，不生成风格、命名偏好或泛泛建议。调用方、实现、配置和测试按需在当前会话补读；`supplements` 必须为空，不递归追加分析。未知输入或证据缺口写明确局限，不作为已确认缺陷。
- **问题复核**：只有包含候选问题的分析批次创建一个独立复核 Session；同批多项问题合并复核，不按问题数量开会话。复核材料只分配候选引用涉及的原始片段，必要外部上下文仍可通过 MCP 读取。复核须逐项判定全部候选，不展开第二轮全面搜索；无问题批次不复核、不伪造复核结果。
- **程序报告**：分析全部有效，候选问题所需复核全部有效，全部会话停止已有证明、报告保存后完成。报告明确无问题结论未经独立复核、排除范围和未解决证据缺口，不声称保证无缺陷或质量等价。

若固定分析批次为 B，其中有候选问题的批次为 F，正常成功路径的 Session 数为 B + F，0 ≤ F ≤ B；规划和递归扩展均为零。失败重试仍追加不可变新代次，不包含在该数量公式内。同会话协议修正、长度续接、冻结任务预算与停止证明沿用公共合同，不新增隐藏模型步骤或改变其预算轴。

V2 批次输入持有 `LIGHTWEIGHT_V2` 策略标识；历史缺省仍为 V1。升级不改写旧合同、快照、计划、输入摘要或已有 Session，不自动取消/重跑已有任务。V2 本身没有数据库迁移或运行中切换策略；当前新任务使用 V3。

## 版本 1 四阶段与计划（已有任务恢复）

1. **冻结证据**：稳定单元以增量 diff hunk、全面文件内可定位片段为基础。可识别的类型/函数入口用于切分提示；超大行为带续接位置。单片含定位头小于 24,000 字符，规划和分析初始材料不超过 48,000 字符。
2. **规划范围**：每页最多 12 单元，模型按 API 两端、调用链、共享结构、状态更新与展示、实现与测试提出分组。服务端验证每个必审单元恰好一个主要归属，排除单元仍需保留理由。全部组冻结后按每页 20 组检查跨模块关系。不同组的同文件相邻片段由程序补上必查关系，防止容量拆片丢失衔接。
3. **功能分析**：每批提交全部单元的处理说明、代码证据、候选问题和局限。可补读全项目上下文。新增独立检查以补充组候选提交，必须有新的冻结上下文、真实单元和有界容量；接受后原子追加批次及计划修订，保留原计划。普通与关系分析都支持补充批次。
4. **独立复核与报告**：分析批次一旦有效即可创建独立复核，不等待无关分析。冻结关系另有分析与独立复核批次。复核须覆盖所有分配单元和候选问题，包括未发现问题的结论，独立读取证据。结论为支持、待确认、不成立、重复。重复只可指向本批已支持问题或同任务先前已接受的独立复核支持问题，禁止循环；报告保留关联位置与来源。

计划和候选有显式字数及集合上限，超限返回可修正的错误，不丢弃尾部内容后声称覆盖。首版没有全语言调用图；分组与衔接的语义质量仍依赖分析和独立复核，不把目录/读取完成当作没有缺陷。

## 恢复、进度与完成

批次复用冻结并发设置（默认 4，允许 1–16）。未知创建、投递和停止状态占窗口；停止没有证明前保留阻断。任务预算与超时沿用原合同，手动重试不重置累计预算。成功批次和读取结果保留，失败批次在其余独立工作结束后统一选择重试，生成新的会话和代次；恢复只使用当前代次，保留不可变失败历史。

已接受候选但远端持续忙碌的批次采用[模板批次收尾与诊断](seven-feature-contract.md#模板批次收尾与诊断)：保存候选，经过正常结束窗口后仅停止该会话，持久化正向停止证明再收束。未交卷批次的无活动告警不自动终止模型；人工停止仍须精确证明，成功批次不重做。诊断可按批次查看并复制安全摘要，无需直接登录受控 OpenCode。

V110 增加独立版本/文件/读取/计划修订表，扩展模板 ID 和批次用途约束，保留旧合同、报告、请求键、会话与候选回执。任务删除按外键依赖显式清理。overview 只投影当前冻结策略的阶段、版本、计划修订、批次数和失败数；批次摘要按时间加 ID 分页，正文按需读取，SSE 只触发刷新。

对应冻结版本所需的全部分析与复核有效（V1 还包含补充和关系检查），全部会话停止已证明、报告已保存后方可完成。执行失败不能作为局限跳过；有效结果中的待确认项可以完成带明确局限的报告。报告由程序生成主报告、当前问题、功能详情、覆盖清单与待确认/局限，不追加全量总结模型。区分变化相关、附带存量与引入归因不明；未发现问题不等于证明无 bug。

## 验证边界

使用真实临时 Git 历史和模拟 Provider 验证日期、最终树、覆盖/引用、权限、编排、报告与恢复。人工标注夹具验证审查输入与候选/复核判定的传递。模拟候选验证协议，不证明真实模型能找出这些缺陷；未进行真实模型试跑时不得声称模型准确率已验证。
