# 冻结版本代码审查合同

本合同持有 `SNAPSHOT_CODE_REVIEW` 版本 1 的行为。它与 `CODE_REVIEW` 历史提交审查、贡献周报、需求代码评审分别冻结合同。公共入口、报告路径、幂等确认与正式 Start 沿用[模板任务合同](seven-feature-contract.md#内置模板任务)，冻结版本审查由独立协调器执行，不采用历史模板的逐提交编排。

## 输入与版本

- 目录声明 `DATE_INCREMENTAL` 与 `FULL`；默认日期增量。全面审查请求不携带日期。
- 日期按北京时间 `[开始日 00:00，结束日次日 00:00)` 解析，结束当天包含在范围内。首次执行在任务自有 bare 仓库冻结所选分支来源 SHA。
- 增量完整遍历来源 SHA 的第一父链，按从新到旧拓扑顺序分别选择 committer 时间严格小于两个边界的第一个提交。时间倒序不提前剪断，记录异常。该规则推算当前主线历史，不能证明当时分支位置或部署状态。
- 冻结来源、基线、目标、树、时间范围、选择依据和采集时间。结束时间尚未来临时只覆盖已采集历史，不等待或监控未来提交。恢复与重试不重解日期和分支。
- 无边界版本、浅历史、历史数量或单次输出超限，在模型调用前阻断；不退回全面审查。沿用 Git 2.30.2 能力与采集停止证明。
- 增量比较最终树，支持新增、删除、重命名、模式变化；同 SHA 或不同 SHA 同树均不调用模型。全面审查列出冻结 tip 的目标文件。

## 证据与权限

角色只能通过专用 MCP 查看冻结目录、分段代码、单文件检索、工作目录、功能组和同任务已接受批次；结构化提交复用版本校验、幂等回执和同会话修正通道。任务、批次、Attempt、Session、托管运行代次、SHA 与 blob 均须匹配。用户 MCP、项目命令、原生文件读取、编辑和 question 不开放。仓库文本不能改变这些权限。

共享 `DocumentCodeContentCache` 的底层代码缓存按任务、SHA、blob 隔离，缓存命中后仍写当前角色读取凭据。一次最多读取 200 行、32,000 字符，每批最多 2,048 个不同读取片段。搜索不是读取凭据。引用须匹配本角色实际读取的版本、文件、blob、完整行范围和原文；当前缺陷须含目标证据。删除问题可以同时引用基线删除位置与目标残留调用。

敏感文件、符号链接、子模块、二进制/非 UTF-8 文件及默认第三方产物目录保留排除或局限；不跟随链接，不运行过滤器。配置、迁移、构建和启动源码在可读范围内照常审查。未知语言可做文本检查，但不宣称语法或跨语言调用图完整。本轮不运行目标项目的构建、测试或脚本，不自动修改代码。

## 四阶段与计划

1. **冻结证据**：稳定单元以增量 diff hunk、全面文件内可定位片段为基础。可识别的类型/函数入口用于切分提示；超大行为带续接位置。单片含定位头小于 24,000 字符，规划和分析初始材料不超过 48,000 字符。
2. **规划范围**：每页最多 12 单元，模型按 API 两端、调用链、共享结构、状态更新与展示、实现与测试提出分组。服务端验证每个必审单元恰好一个主要归属，排除单元仍需保留理由。全部组冻结后按每页 20 组检查跨模块关系。不同组的同文件相邻片段由程序补上必查关系，防止容量拆片丢失衔接。
3. **功能分析**：每批提交全部单元的处理说明、代码证据、候选问题和局限。可补读全项目上下文。新增独立检查以补充组候选提交，必须有新的冻结上下文、真实单元和有界容量；接受后原子追加批次及计划修订，保留原计划。普通与关系分析都支持补充批次。
4. **独立复核与报告**：分析批次一旦有效即可创建独立复核，不等待无关分析。冻结关系另有分析与独立复核批次。复核须覆盖所有分配单元和候选问题，包括未发现问题的结论，独立读取证据。结论为支持、待确认、不成立、重复。重复只可指向本批已支持问题或同任务先前已接受的独立复核支持问题，禁止循环；报告保留关联位置与来源。

计划和候选有显式字数及集合上限，超限返回可修正的错误，不丢弃尾部内容后声称覆盖。首版没有全语言调用图；分组与衔接的语义质量仍依赖分析和独立复核，不把目录/读取完成当作没有缺陷。

## 恢复、进度与完成

批次复用冻结并发设置（默认 4，允许 1–16）。未知创建、投递和停止状态占窗口；停止没有证明前保留阻断。任务预算与超时沿用原合同，手动重试不重置累计预算。成功批次和读取结果保留，失败批次在其余独立工作结束后统一选择重试，生成新的会话和代次；恢复只使用当前代次，保留不可变失败历史。

V110 增加独立版本/文件/读取/计划修订表，扩展模板 ID 和批次用途约束，保留旧合同、报告、请求键、会话与候选回执。任务删除按外键依赖显式清理。overview 只投影四阶段、版本、计划修订、批次数和失败数；批次摘要按时间加 ID 分页，正文按需读取，SSE 只触发刷新。

所有必需分析、补充、关系检查及独立复核有效，全部会话停止已证明、报告已保存后方可完成。执行失败不能作为局限跳过；有效结果中的待确认项可以完成带明确局限的报告。报告由程序生成主报告、当前问题、功能详情、覆盖清单与待确认/局限，不追加全量总结模型。区分变化相关、附带存量与引入归因不明；未发现问题不等于证明无 bug。

## 验证边界

使用真实临时 Git 历史和模拟 Provider 验证日期、最终树、覆盖/引用、权限、编排、报告与恢复。人工标注夹具验证审查输入与候选/复核判定的传递。模拟候选验证协议，不证明真实模型能找出这些缺陷；未进行真实模型试跑时不得声称模型准确率已验证。
