# 固定报告格式

模板任务版本 2 使用 `REPORT_LAYOUT_V2`。三份 Markdown 模板随 JAR 内置，确认任务时将模板正文、版本和 SHA-256 一同保存到不可变合同。模型只提供结构化分析、问题、证据引用和评分等级；标题、章节、表头、评分公式、空值说明与渲染顺序由程序持有。

旧合同没有报告模板字段时，继续使用原 V1 渲染器；已经生成的报告正文不因升级而改写。新任务才使用下列格式。报告仍须经过确定性证据校验和原有独立双评审，格式固定不代表自动降低验收标准。

## 三份报告

| 报告 | 文件 | 固定章节 |
| --- | --- | --- |
| 代码审查 | `code-review.md` | 审查范围、结论摘要、问题清单、逐提交审查、覆盖与局限 |
| 项目贡献总报告 | `contribution-report.md` | 统计范围、项目贡献概览、贡献排名、人员评分依据、项目工作与问题明细、内置评分标准、统计口径与局限 |
| 个人贡献周报 | `contributors/{identity}.md` | 统计范围、贡献概览、工作明细、问题与改进建议、评分依据、内置评分标准、统计口径与局限 |

对应内置文件：[代码审查模板](../src/main/resources/report-templates/code-review-v2.md)、[贡献总报告模板](../src/main/resources/report-templates/contribution-report-v2.md)、[个人周报模板](../src/main/resources/report-templates/personal-contribution-v2.md)。

由同一生产渲染器生成的虚构数据示例：[代码审查报告](examples/template-reports/code-review.md)、[项目贡献总报告](examples/template-reports/contribution-report.md)、[个人贡献周报](examples/template-reports/contributors/alice.md)。示例不代表真实人员、真实代码审查或实际模型输出。

## 字段与空范围

- 范围表固定展示项目、分支来源、冻结提交、起止日期、北京时间与 committer 口径、提交覆盖、片段覆盖和身份映射快照。个人报告的覆盖数仅指该贡献者关联提交，不把全项目数量当成个人数量。
- 代码审查摘要固定展示严重、高、中、低四级问题数与总数。问题表包含编号、级别、提交、文件与变更前后行号、问题、影响与依据、建议。没有问题时保留章节与表头并说明无已确认记录，不宣称代码没有缺陷。
- 提交明细固定展示提交说明、北京时间、作者、文件增删行、有效量、排除依据、证据引用及分析。空提交和无独有改动的合并也保留记录。
- 贡献排名同时展示提交数、原始量、有效量、五个维度分数与总分；人员评分依据在总报告和个人报告中都保留。数量 30、价值 25、难度 15、质量 20、维护 10，规则由[功能合同的贡献评分](seven-feature-contract.md)和 `ContributionScore` 持有，本次不修改评分算法。
- 没有提交时仍生成完整章节的总报告或审查报告，明确无提交、覆盖数为 0；不虚构人员和个人报告。零有效量人员及机器人保留记录，机器人不参与排名。
- 模型摘要、贡献者名称、提交消息及路径按不可信文本转义，换行不能插入新的章节或表格行。模型候选输入顺序变化不得改变相同证据的报告字节。

## Git 2.30.2 基线

生产采集不使用 `log --since-as-filter`、`check-attr --source` 或 `show --remerge-diff`。遍历完整可达历史后按提交时间筛选，防止提交时间倒序导致漏报；文件属性使用任务自有 index 的 `read-tree` 与 `check-attr --cached`；合并通过临时目录的递归合并生成含冲突标记的独立基线。

这些临时操作不会运行项目构建或测试，也不改变原项目分支、index、文件和提交。流程容量、浅历史、多父合并与停止证明要求继续由[功能合同](seven-feature-contract.md)持有。Git 错误输出安全分类、操作名与退出码，原始诊断中的凭据、URL 和其他任意内容不直接进入报告或数据库。
