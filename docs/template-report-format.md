# 固定报告格式

模板任务从版本 4 起使用 `REPORT_LAYOUT_V3`，将报告组织为主报告（总结）与子报告（详细）。四份 Markdown 模板随 JAR 内置，确认任务时将正文、版本和 SHA-256 保存到不可变合同。模型提供结构化分析、问题、证据引用和评分等级；服务端校验一次后生成各层报告，不额外创建总结或子报告模型会话。

历史 `REPORT_LAYOUT_V2` 合同仍按冻结的三份模板生成原文件；没有报告模板字段的合同继续使用 V1 渲染器。旧报告正文、文件名与保存路径保持原样。层级拆分不改变评分算法或确定性证据校验；完成策略按[模板任务合同](seven-feature-contract.md#内置模板任务)冻结，V7 校验并保存后完成，历史 V1–V6 保留双评审。

## 两类报告

| 模板 | 主报告 | 子报告 |
| --- | --- | --- |
| 代码审查 | 范围、提交和片段覆盖、各严重程度问题数量、前 10 项重点问题与建议、详情入口和局限 | 完整问题清单、逐提交审查目录、每个提交的详细审查 |
| 项目人员贡献周报 | 范围、贡献概览、人员工作摘要与排名、总分、重点问题与建议、详情入口和局限 | 每位贡献者的工作与评分依据、完整问题清单、完整评分标准 |

内置文件：[代码审查总结](../src/main/resources/report-templates/code-review-v3.md)、[项目贡献总结](../src/main/resources/report-templates/contribution-report-v3.md)、[个人贡献详情](../src/main/resources/report-templates/personal-contribution-v3.md)、[通用详情](../src/main/resources/report-templates/report-detail-v3.md)。

主报告的链接进入详细报告，所有子报告有返回总结入口，提交目录链接到对应提交，个人详情链接到评分标准。使用经过编码的相对 Markdown 链接，任务页面在同一报告版本内预览，完整文件夹或 ZIP 解压后仍能跳转。正文按所选制品首次读取和缓存，打开页面不批量请求所有正文。

由生产渲染器生成的虚构数据示例：[代码审查总结](<examples/template-reports-v3/代码审查_模板示例项目(虚构)_20260905-20260911_001/代码审查_模板示例项目(虚构)_20260905-20260911_001.md>)、[项目贡献总结](<examples/template-reports-v3/项目贡献周报_模板示例项目(虚构)_20260905-20260911_001/项目贡献周报_模板示例项目(虚构)_20260905-20260911_001.md>)。示例不代表真实人员或实际项目结论。

## 名称、序号与目录

文件名为 `报告类型_项目_开始时间-结束时间_序号.md`；目录使用同样的名称并去掉 `.md`。时间取任务所选日期范围，使用 `yyyyMMdd`，不是执行耗时或生成时间。项目名首次分配报告编号时保存，后续项目改名不改变这次执行的名称。

- 同一规范化报告类型、项目名和日期范围使用数据库持久化递增序号，从 `001` 开始；超过 999 继续递增。重复生成的新任务及产生报告的新返修轮次分别分配新编号。
- 同一执行轮次的文件写入重试、进程恢复沿用原编号。分配后中止可留下编号空缺；删除任务也不回收编号，避免复用保留在磁盘上的历史报告名。
- 主报告文件与外层文件夹同名；明细目录保留同一项目、日期和本轮编号。逐提交、个人详情等子文件按稳定顺序编号；个人报告类型附带姓名，同名人员仍有不同序号。
- 文件名中的控制符、空白和跨平台非法路径字符替换为短横线，规范化 Unicode 并限制文件名长度。序号命名空间忽略大小写，规范化后同名项目共用计数器，避免同目录冲突。
- 指定文档路径时直接在该目录下创建命名文件夹；未指定时在任务工作目录的 `reports/` 下创建。写入仍先保存不可变制品，再原子落盘；拒绝符号链接、目录越界和覆盖内容不一致的既有文件。

例如：

```text
代码审查_示例项目_20260905-20260911_001/
├── 代码审查_示例项目_20260905-20260911_001.md
└── 代码审查明细_示例项目_20260905-20260911_001/
    ├── 问题清单_示例项目_20260905-20260911_001.md
    ├── 提交审查目录_示例项目_20260905-20260911_001.md
    ├── 提交审查_示例项目_20260905-20260911_001.md
    └── 提交审查_示例项目_20260905-20260911_002.md
```

V79 新增编号计数器与执行轮次目录记录。分配在短事务内完成，文件写入在事务外。删除任务先显式删除目录记录，计数器保留。

页面支持单份 Markdown 和“下载整套报告”。整包接口以所选制品校验 Task 归属，再读取同一次执行的报告；ZIP 保留外层目录及相对路径，不包含其他版本、分析 JSON 或原始 Git 快照。读取正文前限制为 64 MiB、10000 个文件，超限提示从已保存目录读取。旧版报告保留原单文件下载。

## 字段与空范围

- 范围表展示项目、分支来源、冻结提交、起止日期、北京时间与 committer 口径、提交和片段覆盖、身份映射快照。个人覆盖数仅统计其关联提交。
- 完整问题表保留稳定全局编号、级别、提交、文件与变更前后行号、问题、影响与依据和建议。同一问题在提交或个人详情中的编号与完整清单一致。
- 提交详情保留说明、北京时间、作者、文件增删行、有效量、排除依据、证据引用和分析。空提交、无独有变更的合并也保留记录。
- 主报告展示个人总分与排名；个人报告展示原始量、有效量、五维分数与完整理由。评分标准独立成子报告，数量 30、价值 25、难度 15、质量 20、维护 10，仍由 `ContributionScore` 持有。
- 空日期范围保留总结与详情导航并明确无提交，不虚构人员、问题或个人报告。零有效量人员、机器人保留记录，机器人不参与排名。
- 摘要、姓名、提交消息和路径按不可信文本转义；换行不能插入章节或表格行。候选输入顺序改变不得改变同一证据的报告字节。

## Git 2.30.2 基线

生产采集不使用 `log --since-as-filter`、`check-attr --source` 或 `show --remerge-diff`。遍历完整可达历史后按提交时间筛选，防止提交时间倒序导致漏报；文件属性使用任务自有 index 的 `read-tree` 与 `check-attr --cached`；合并通过临时目录的递归合并生成含冲突标记的独立基线。

这些临时操作不会运行项目构建或测试，也不改变原项目分支、index、文件和提交。流程容量、浅历史、多父合并与停止证明要求继续由[功能合同](seven-feature-contract.md)持有。Git 错误输出安全分类、操作名与退出码，原始诊断中的凭据、URL 和其他任意内容不直接进入报告或数据库。
