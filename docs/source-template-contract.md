# 源码模板任务合同

本合同持有 `UNIT_TEST_DEVELOPMENT`（单元测试开发）与 `DETAILED_DESIGN_WRITING`（详细设计编写）的路径输入、来源、执行、恢复和交付行为。两个模板独立持有版本，首版各为 `1`。文档模板与历史 Git 报告模板继续使用各自冻结合同，不迁移成源码模板。

## 输入与正式开始

目录能力声明 `sourcePath`、`testOutputPath`、`documentOutputPath`，旧字段保持兼容。输入包括项目、模板版本、源码路径、可选输出目录与补充要求。源码支持项目内单文件或递归目录，不选择分支，也不使用上传文档。

`POST /api/template-tasks/source-runs/preview` 只检查范围与测试配置，不创建记录、Designer、Task、队列、租约或模型会话。展示处理文件数、模块数、输出位置和排除原因。预检不是正式冻结；输入变化后必须重新预检。

`POST /api/template-tasks/source-runs` 以 `requestKey` 幂等创建 `PENDING_START` 记录，冻结参数、模板版本、模型与预算。相同键及参数返回原记录，参数不同则冲突。`POST /{id}/start` 才采集实际源码；所有控制操作使用请求键、`expectedVersion` 和本地 UI 头。路径选择取消、项目或模板切换、迟到响应不能覆盖当前输入。创建成功进入详情，由用户正式开始。

## 冻结源码与覆盖

来源使用项目当前目录，允许详细设计读取未提交内容。源码和测试输出路径必须在 canonical 项目目录内，不允许上级跳转或符号链接。依赖、构建输出、工具目录、敏感文件与生成代码按读取策略排除，并保留原因。项目其他可读源码可以作为只读依赖上下文，不扩大目标覆盖或写入授权。

采集执行两次文件清单与内容哈希检查；前后存在活动 writer 或文件持续变化时等待。单文件正文上限 2 MB、可读项目正文合计 64 MiB、清单 50000 项、每次扫描 30 秒，超过限制保留未完成事实。先提交清单身份，再按内容哈希保存正文；恢复必须补齐同一份快照，不能用新代码替换已冻结输入。无法读取、解析或超过正文上限的目标保存为 `INCOMPLETE`，不折算为成功或普通排除。

单测另冻结私有工作区文件哈希基线，不向模型暴露受保护文件正文。正式 Start 前复核冻结来源；执行中在每个验证器前后校验专用写入范围。漂移必须处理原任务，不允许沿用旧设计写入新代码。新配置需要重新预检；原任务恢复不会重置快照或预算。

## 单元测试开发

来源以真实源码清单绑定 Designer 需求版本、Task、滚动计划和阶段，不能伪造上传文档。共享来源授权查询只识别持久化模板来源；普通 Designer 的人工边界和推荐业务答案策略不变。模型使用会话专属的 `get_source_development_work`、`list_source_development_files`、`read_source_development_file` 读取冻结源码与已有测试，许可绑定项目、目录、角色、执行身份、清单和运行代际。

框架、测试目录、夹具目录与测试命令根据构建配置、技术画像和已有测试识别。首版支持可明确识别的 Maven/Gradle JUnit 或 TestNG、npm Jest/Vitest 与 pytest；无法安全识别自定义目录或测试入口时进入待处理，不安装依赖、不猜测配置。多模块分别冻结映射，Maven 声明的 reactor 命令可包含 `-pl`/`-am`。Git 项目的构建输出须已被忽略且没有已跟踪的产物，否则等待项目维护者处理；模板不会改写 `.gitignore`。

小范围复用单包设计，超过 12 个源码对象或 160000 字节使用既有大型流程。单包出现确证的 `LARGE_TASK_MODE_REQUIRED` 时，可以在停止旧角色后转入滚动包；持久化切换意图，保留原源码、需求正文及已消耗模型预算。普通业务缺口不触发该授权。Task 只由正常确认创建为 `PENDING_START`，正式 Start 继续经过队列、目录租约、Git 分支和未提交文件处理入口。

每个目标源码文件对应批准的正常、边界、异常或关键分支场景。已有有效测试保留并重新执行；不为制造差异要求重复编写。仅允许冻结测试源码与夹具范围内的改动，新增、修改、删除、重命名均检查；禁止范围外新增、删除已有文件、屏蔽测试或弱化已有断言。Java 已有测试使用语法树保留原成员，其他语言不能安全确认已有正文不变时要求在新文件补齐场景。独立 Judge 仍须审查实际测试意义，机械检查不能替代语义评审。

生成的构建输出属于执行产物，不是源码交付。不能通过 `GIT_DIFF` 的范围外新增放行或人工 diff 决策绕过源码模板守卫。业务代码、依赖或构建配置需要修改时进入待处理；业务缺陷导致的测试失败保留验证证据。

最后阶段由服务端补入所有受影响模块的原生测试命令，并在结果收集时独立复核。成功要求目标覆盖闭合、每阶段实际测试通过、范围校验通过、当前成功执行轮次及同批需求/风险双 Judge PASS；两个 Judge 各自完整读取目标源码。不能把构建、文件存在、退出码或模型声明单独当成行为通过。没有适用测试对象时明确说明，不显示测试通过。

源码模板 `COMPLETED` 与关联 Task 的 `AWAITING_DECISION` 分别呈现。模板不自动采用、提交、推送或发布产品内 Task 的执行结果；结果仍由用户在执行详情处置，未处置或有活动租约时不能归档隐藏。

## 详细设计编写

冻结清单按目录与容量形成持久化独立批次，每批最多 12 文件、160000 字节；角色按职责和调用关系组织章节。`SOURCE_DETAILED_DESIGN_V1` 编写，`SOURCE_DESIGN_REVIEW_V1` 独立复核，两者只有冻结源码和候选的专属只读 MCP。作者与复核者的读取记录、候选身份、版本、幂等键和停止证明独立。

每个模块文档覆盖适用的职责、接口、数据结构、核心流程、持久化/事务、状态/并发、异常/权限及源码依据。流程使用 Mermaid，不适用时说明；事实、推断、未知项和建议分开。每个目标文件至少关联一个章节及本角色实际读取的引用（路径、哈希、行号、逐字摘录）。

程序验证完整目标覆盖、完整读取区间、引用、重复标识、候选结构和安全 Markdown。模型不能自行生成 HTML、图片或文档链接；服务端生成目录、文档间导航和源码覆盖清单。复核者完整读取本批源码以及本轮所有模块文档，检查遗漏、错误、图文差异与跨模块矛盾。有问题必须 `REVISE`；修订只重写对应作者批次，其他有效稿件保留，跨模块上下文变化后在原预算内重新复核。

全部批次通过后服务端冻结“总览—模块详情—覆盖清单”Markdown 包及 SHA-256，再写入输出目录。目录采用“本次指定 → 项目默认 → 任务目录”，每次使用 `source-{runId}` 独立子目录。已有外部文件不同内容或符号链接会阻断写入，不覆盖用户文档。恢复继续同版制品。列表仅提供元数据，预览、单篇下载和整包下载来自相同服务端字节。

## 恢复、预算与界面

源码模板、模型批次、Designer、Task、Stage、Attempt、Judge、队列与租约分别持有状态。独立文档批次使用冻结并发窗口；单测在同一目录串行写入。失败批次保留，其他独立批次继续；结束后可以选择失败项重试，成功项不重做。恢复次数、模型尝试数、内容修正次数和原有 Designer/Task 预算分别校验，不用新建任务规避已消耗预算。

创建响应丢失先按精确创建身份查询，投递响应丢失核对持久化消息与请求摘要；未知身份不能盲目重发。接受候选后仍等待会话终态，或接受 60 秒后取得停止证明；接受回执不等于业务完成。已接受且已证明停止的结果可以无新模型调用恢复。取消先记录停止意图，只有所有相关模型和执行 owner 证明停止才进入 `CANCELLED`。不明停止保持阻断，不释放对应租约或启动重叠 writer。

详情展示冻结、设计/编写、执行验证、复核的真实状态和逐文件依据，失败原因保留。正文按请求加载，批次与覆盖分页；SSE 只合并通知刷新，断线使用状态读取，不推进生命周期。统一历史视图将源码发起记录与关联 Task 合为一行，筛选、状态计数、分页和归档使用同一服务端范围；关联执行待处置状态必须可见。

## 验收与兼容

V127 起追加源码模板表与候选所有者，历史迁移不可改写。候选表扩展在复制历史行之前校验 owner/scope，保留原候选、读取、尝试、外键和结算守卫；非法旧数据升级失败关闭。

模拟 Provider 证明生命周期、失败与恢复，实际测试进程证明测试执行，两者都不能代替真实 Provider 验收。真实验收使用当前配置模型及两个独立 Java 小样例，分别保留输入快照、冻结预算、原运行身份、证据与结果。模型或环境不可用时记录真实阻塞，不更换任务伪装通过。构建、JAR、本地运行、Git 提交及远端发布按照[开发与交付](development.md)分别记录。

源码单测的 GIT_DIFF 只校验实际差异的路径和禁止删除，不强制每个阶段产生新文件差异；已有测试足够或最后仅执行整体回归时，仍须通过实际测试和独立双 Judge。服务端编译时固定 requireChanges=false，不由模型把“产生修改”当成成功条件。历史已冻结 Task 不被静默重写。
