# Git 账号管理

Loopper 可独立管理 HTTP(S) Git 账号：设置页维护一个全局默认账号，项目默认继承，也可选择独立账号。账号必须绑定到明确的服务器协议、主机和端口。不同服务器不会共用凭据。此功能不修改系统 Git 配置，也不依赖 IDEA 凭据。

## 页面与 API

- 设置 → 全局 Git 账号：填写服务器地址、用户名、认证方式和密码或访问令牌，保存后供项目继承。
- 项目 → Git 与 GitLab → Git 账号：默认继承全局账号，可改为独立账号，也可恢复继承。
- “验证连接”针对完整仓库地址执行只读 `ls-remote`。项目留空时读取 origin；全局验证必须填写仓库地址。验证草稿不会保存，也不证明推送权限。
- 已保存密码不回显；留空保持不变。更换服务器、用户名或认证方式必须重新填写。保存冲突要求重新加载。
- HTTP 会显示传输未加密提示；HTTPS、密码登录、Token 权限及过期策略受实际 Git 服务器控制。配置后仍需在令牌过期、撤销或账号权限变化时更新。

`GET/PUT /api/git-credentials` 和 `POST /api/git-credentials/test` 使用可选 `projectId` 区分全局与项目。写入和验证要求本地 UI 标识；请求含版本，保存使用 CAS 和元数据审计。响应只返回账号元数据与是否已配置，不返回秘密或存储引用。此配置不提供给模型或 MCP。

项目页合并为一个“Git 与 GitLab”入口，账号与 GitLab 仓库/证据使用同一窗口分区管理，各自保存。Git 账号与 GitLab API Token 的权限、存储和作用域保持独立。GitLab 接口地址明确支持 HTTP/HTTPS，设置页和账号页对 HTTP 显示传输提示；原有禁止重定向、实例匹配与冻结校验继续生效。

## 生效与隔离

后续远程分支读取、任务准备 fetch、模板及文档快照 fetch、正式发布 push 使用项目有效账号。私有快照或执行目录必须携带原登记项目身份。账号更新不改变已冻结提交、快照、历史任务或正在运行的 Git 子进程，也不自动重试未知结果的写操作。

全局账号仅匹配同源 HTTP(S) URL；不同源或未配置时保留原系统 Git 行为。项目独立账号与远端不匹配时明确失败，不降级到全局账号。独立项目恢复继承后使用当前全局账号。停用全局账号不影响项目独立账号。SSH 继续使用原系统配置。

凭据仅通过受管 Git 子进程环境提供，不进入参数、URL、脚本、临时明文文件或日志；使用 Git 2.30.2 支持的命令级配置，关闭交互提示、追踪、HTTP 重定向和递归子模块抓取。凭据请求使用服务器来源限定的 Authorization 头，不写入仓库或用户配置。Git 错误返回分类后的中文原因，禁止回传原始 stderr 中的秘密。

## 存储、迁移与恢复

V112 追加全局/项目设置及审计表，不修改既有记录。SQLite 仅存服务器、用户名、模式、版本及不可变密文引用。密码或 Token 使用 AES-GCM 密文写入数据目录 `git-secrets/`；目录权限 0700、文件 0600，Windows 使用用户专属 ACL，拒绝符号链接。密文文件先在事务外原子生成，短事务内 CAS 保存引用及审计；失败产生的未引用密文不被自动删除。

所有受管子进程启动前移除 Git 和数据库主密钥环境变量，OpenCode、验证命令和 Git 均不能继承主密钥。

独立 Git 主密钥来自 `LOOPPER_GIT_MASTER_KEY`（32 字节随机值的 Base64），否则首次使用在 `~/.opencode-loopper/keys/git-master.key` 创建。Git 与数据库凭据使用独立密钥和目录。已有密文而主密钥丢失、错误或权限不安全时失败关闭，不生成新密钥覆盖旧身份。恢复必须同时恢复正确密钥与数据；主密钥应单独保管，不随普通数据导出、日志或发布包分发。停用和覆盖不删除历史密文。

数据库凭据复用公共加密实现，但原密钥位置、格式、AAD 和错误合同保持兼容。Git 账号不代替 GitLab API/MCP Token，不扩大 AI 权限。
