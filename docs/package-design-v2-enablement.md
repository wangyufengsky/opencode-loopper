# V2 确定性加固与默认启用（0.3.75）

按用户 2026-09-07 的明确要求，修复已复现的确定性漏洞后，将新建工作包会话默认设为 V2。该启用决定不改写三批评测的历史 `FAILED_KEEP_DISABLED` 结论，也不表示自然语言完整性已经通过原定质量门。

## 默认与兼容

`LOOPPER_PACKAGE_DESIGN_V2_ENABLED` 默认 `true`，仍通过既有工作包 MCP 通道工作。V2 自动冻结仓库证据与来源，因此无须另开只针对 V1 的 `LOOPPER_PACKAGE_DESIGN_EVIDENCE_ENABLED`。每个运行只开放匹配冻结版本的提交工具。

开关只决定新建持久工作包会话的 profile。已有 V1 会话、进行中的候选、旧 Role Pack 和已接受结果不升级；已有 V2 会话也不会因关闭开关变为 V1。需要回滚新会话的选择时，可在下次启动时显式设置 `LOOPPER_PACKAGE_DESIGN_V2_ENABLED=false`，历史恢复和停止路径继续可用。此次交付没有重启或部署服务。

## 修复的确定性边界

1. 冻结原文要求删除全部现有测试、移动“该文件”等集合或指代操作时，原有精确路径提取可能漏掉源端。现在在 V2 来源预检中识别有界的任务级文件删除/移动请求，结合既有精确路径检查返回 `PACKAGE_GAP_PROVEN_CONFLICT / WAITING_INPUT`。否定、示例及“实现删除文件功能”等业务行为不直接当成删除仓库文件的命令。模型不能把“保留”和“删除”写成 `any` 来解除硬约束。这是有界词面分类，不宣称能识别所有自然语言指令。
2. 候选可在交付物中新增路径，旧编译器会将其并入执行范围。现在 V2 接受前由纯 `PackageDesignScopeGuard` 独立核对最终 Stage 和每个 `GIT_DIFF`：允许路径必须是冻结范围子集，禁止路径必须保留，必须有范围验证器，`forbidDeletes` 必须为 `true`。无法证明或规则计算超限均阻断，且不保存部分计划。
3. 冻结允许范围只来自服务端 scope、原始需求中的写入义务或既有技术栈路径策略，提取使用空候选 Catalog。普通单包的“当前完整软件需求”沿用服务端既有 Java/Python/其他栈默认路径；候选路径不能反向扩大授权。明确文件路径不能被当成可继续扩展的目录前缀。

范围守卫不进行文件、网络或模型调用；仓库事实仍在候选校验之前冻结。权限、拥有者、版本、完整对象重提、幂等、UTF-8 限额和远端停止确认保持原有约束。安全范围冲突进入本地反馈；普通可修复候选错误仍允许同会话重提。
